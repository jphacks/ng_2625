## 製品概要
生徒の手書き数学答案から、つまずきの原因候補を整理し、大学生の塾講師や家庭教師の指導を支援するWebアプリ。

### 特長
#### 1. 特長1
**数学の誤概念データから学習した独自モデルによる推定**

Eediの数学誤概念データセットで追加学習したモデルを用い、問題文・正答・生徒の誤答から、つまずきの原因候補を推定する。日本の計算分野に関係する誤概念を候補として選び、問題の形式や単元に応じて絞り込むことで、講師が確認すべき考え方を整理して提示する。

#### 2. 特長2
**途中式を手がかりに、誤りが生じた箇所を確認**

対応範囲の問題では、計算エンジンが正答や途中式の変形を検証する。答案上で確認できる誤りと、独自モデルが推定する原因候補を組み合わせ、講師が根拠と照らし合わせて判断できるようにした。

#### 3. 特長3
**普段の紙の答案から、問題・途中式・解答を抽出**

手書き答案の写真から数式や文章を読み取り、「問題文」「途中式」「最終解答」に分けて抽出する。対応範囲内のワークやテストを分析の入口にでき、講師が元画像との照合・修正や、範囲を指定した再読み取りを行ってから分析へ進める。

### 背景(製品開発のきっかけ、課題等）
大学生が塾講師として指導する場面では、教育を専門に学んでいない学生も、生徒の理解度に合わせた説明や学習計画を求められる。講師ごとの指導経験や教え方の違いによって、指導の質にばらつきが生じやすい点に着目した。

特に、復習する内容や宿題を講師の裁量で決める際には、「生徒が何を理解できていないのか」「どの考え方から確認すべきか」を判断する難しさがある。答案の正誤だけではつまずきの背景を把握しにくく、経験の浅い講師にとって負担になり得る。

そこで、数学の答案から細かな苦手要素の候補を整理し、講師が生徒に何を確認するかを考えるためのアプリを考案した。答案の根拠と原因候補を示すことで、大学生講師の判断を支え、生徒一人ひとりに合った学習支援につなげることを目指す。

### 製品説明（具体的な製品の説明）
本製品は、生徒の数学の答案写真から、つまずいている考え方の候補を推定し、塾講師や家庭教師の指導を支援するWebアプリである。

答案を撮影・アップロードすると、画像認識APIが問題文・途中式・最終解答を抽出する。講師が元画像と照合して読み取り結果を確認・修正した後、正答との照合、途中式の検証、独自モデルによる誤概念候補の推定を行う。結果は、つまずきの単元・考えられる原因・指導時の声かけを含む日本語レポートにまとめる。

**利用の流れ**

1. 答案を撮影・アップロードする。
2. 読み取り結果を確認・修正し、必要に応じて正答を入力する。
3. 正誤や途中式の誤りを確認し、関連する誤概念の候補を推定する。
4. 日本語レポートを参考に、生徒への問いかけや説明内容を検討する。

計算・方程式に加え、比・割合・速さなどの文章題にも対応する。式だけでは正答を計算できない問題では、講師が入力した正答や答案の丸つけ情報を使って正誤を確認する。現在の誤概念推定は計算分野を対象としており、関数・図形・高校数学などは対象外として扱う。詳細は[Web版README](./keisan-note-web/keisan-note-web/README.md)に記載している。

**分析のイメージ**

例えば、`3x + 4 = 13` に対して生徒が `3x = 13 + 4` と変形した場合、「両辺から4を引く場面で右辺に4を足している」という誤りを確認する。そのうえで、等式を保つ操作や移項時の符号の扱いが未定着である可能性を示し、講師が「左辺の＋4を消すには、両辺にどのような操作をしますか？」と確認する手がかりにつなげる。

これは機能を説明するための例であり、一度の誤答から理解不足を確定するものではない。不注意や書き落としなどの可能性も含め、講師が生徒に確認するための判断材料として使う。

### 解決出来ること
答案に表れた誤りと原因候補を整理することで、生徒のつまずきを把握し、次の指導を考える作業を支援する。具体的には以下の3点が挙げられる。

- **生徒のつまずきを具体的に確認できる**  
  符号の扱い・分配法則・同類項の整理など、正誤や合計点だけでは分かりにくい細かな学習要素を、答案の根拠と照らし合わせて確認できる。
- **復習・宿題を選ぶ際の判断を支援する**  
  つまずいている可能性のある要素と指導時の声かけを示し、講師が復習内容や宿題を検討するための材料を提供する。
- **講師間で確認する観点をそろえる手がかりになる**  
  答案の根拠・原因候補・声かけを共通の形式で整理し、経験の浅い大学生講師が指導を組み立てる際の参考にできる。

講師の負担軽減や指導品質への効果は、今後の現場での試験導入を通じて検証する。

### 今後の展望
- **現場での有用性の検証**  
  実際の個別指導塾で試験導入し、通常の指導や汎用AIを利用する場合と比較して、分析の適切さ・使いやすさ・講師の負担軽減効果を検証する。
- **分析から指導・復習への接続**  
  生徒への問いかけを充実させ、確認問題や苦手要素に応じた復習内容の提示機能を追加する。また、普段使用する教材と連携し、具体的な宿題を選びやすい仕組みを目指す。
- **診断精度と信頼性の向上**  
  学習に使用していない日本語の手書き答案で評価し、講師による訂正を通じて改善する。答案から確認できる誤りと原因の仮説を区別し、根拠が不足する場合は追加の確認を促す。
- **学習履歴と指導内容の共有**  
  後日の類題で理解の定着を確認できるようにし、講師間で分析結果や指導内容を引き継げる仕組みを整える。
- **安定した運用と情報管理**  
  固定URLでの常設公開、講師ごとのログイン、答案データの保存・削除・外部送信ルールを整備する。通信障害やAPI利用上限への対応、動作速度・運用費用の改善、問い合わせ体制の整備を進める。

### 注力したこと（こだわり等）
- **数学の誤概念データセットを用いた独自推論モデルの構築**  
  Sentence Transformersの既存モデルをベースに、Eediの数学誤概念データで追加学習したモデルを構築した。問題文・正答・生徒の誤答と、誤概念の説明をベクトル化し、類似度によって原因候補を順位付けする。Web版では全2,587件から日本の計算分野に関係する764件を候補として残し、問題形式や単元に応じてさらに絞り込んでいる。
- **手書き答案から、誤りを保ったまま数式を抽出すること**  
  画像認識APIを活用し、問題文・途中式・最終解答を分けて抽出する処理を設計した。分析に必要な生徒の誤答が正しい式に補正されないよう指示を工夫し、負号や分数などの読み取り違いを講師が確認・修正できるようにした。範囲を指定した再読み取りにも対応している。
- **数式の検証と誤概念推論の組み合わせ**  
  計算エンジンによる正答・途中式の検証と、独自モデルによる誤概念候補の推定を組み合わせた。モデルの入力は問題文・正答・生徒の解答とし、途中式は別の検証処理とレポートに活用する。答案上で確認できる誤りと、背景にある考え方の候補を、講師が照らし合わせて判断できる構成を重視した。
- **紙の教材を使う大学生講師に合わせた設計**  
  普段のワークやテストの答案写真を入口に、つまずきの単元・原因候補・指導時の声かけを整理する。経験の浅い講師が、生徒に何を確認し、どう説明するかを考える手がかりになることを目指した。

## 開発技術
### 活用した技術
#### API・データ
* **Gemini API**：手書き答案の読み取り、文章題の英訳、日本語レポートの作成。
* **Eediの数学誤概念データセット**：誤概念推定モデルの追加学習、原因候補と学習単元の対応付け。

#### フレームワーク・ライブラリ・モジュール
* **Python / PyTorch / Sentence Transformers / Transformers / NumPy**：モデルの構築とPython版の推論。ベースモデルは `sentence-transformers/all-MiniLM-L6-v2` を使用。
* **FastAPI / Uvicorn**：`predict/` にあるPython版の推論API。
* **HTML / CSS / JavaScript**：Web画面、数式の検証、ブラウザ内でのモデル推論。
* **Cloudflare Pages / Pages Functions**：Web版の配信、Gemini APIの中継、合言葉によるアクセス制限。
* **Node.js / Wrangler**：モデルのWeb向け変換、候補ベクトルの作成、Web版の起動・公開。

#### デバイス
* **カメラ付きスマートフォン**：紙の答案の撮影・アップロード。
* **PC・スマートフォンのWebブラウザ**：読み取り結果の確認・修正、分析、日本語レポートの閲覧。

### 独自技術
#### ハッカソンで開発した独自機能・技術
* **誤概念を検索・順位付けするモデル**  
  問題文・正答・生徒の誤答を入力し、誤概念の説明との類似度から候補を推定する。  
  実装：[`predict/app.py`](./predict/app.py)、[追加学習済みモデル・モデルカード](./predict/misconception_model/)
* **誤答を保った答案の読み取り・構造化**  
  問題文・途中式・最終解答を分けて抽出し、講師による照合・修正・部分的な再読み取りにつなげる。  
  実装：[`lib/prompts.js`](./keisan-note-web/keisan-note-web/lib/prompts.js)、[`functions/api/ocr.js`](./keisan-note-web/keisan-note-web/functions/api/ocr.js)
* **数式の検証と単元に応じた候補の絞り込み**  
  計算エンジンで正答や途中式を検証し、日本の学習単元に応じた誤概念候補を使って分析する。  
  実装：[`public/index.html`](./keisan-note-web/keisan-note-web/public/index.html)、[`scripts/subjects.mjs`](./keisan-note-web/keisan-note-web/scripts/subjects.mjs)
* **独自モデルをブラウザで実行する仕組み**  
  モデルを半精度化・分割して配信し、独自のBERT推論処理で実行する。画像の読み取り・翻訳・日本語レポートの作成にはGemini APIを使用する。  
  実装：[`public/bert.js`](./keisan-note-web/keisan-note-web/public/bert.js)、[`scripts/pack-model.mjs`](./keisan-note-web/keisan-note-web/scripts/pack-model.mjs)

最新版のWeb版は [`keisan-note-web/keisan-note-web/`](./keisan-note-web/keisan-note-web/) に配置している。起動方法と詳しい対応範囲は[Web版README](./keisan-note-web/keisan-note-web/README.md)を参照。
