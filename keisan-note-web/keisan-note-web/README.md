# ケアレスノート（Web版）

答案の写真から計算ミスの原因を推定し、講師向けのレポートを日本語で作るWebアプリです。
Cloudflare Pages に公開すると、PC・スマートフォンのWebブラウザから利用できます。初回のモデル読み込み時間や処理速度は、端末と通信環境によって変わります。

リポジトリのルートから実行する場合、このREADMEがある `keisan-note-web/keisan-note-web/` を作業フォルダにしてください。ルートの `server.py` は旧構成の試作で、このWeb版の起動には使いません。

| 処理 | どこで動くか |
|---|---|
| 答案の読み取り | Gemini API（中継プログラムがキーを持つ） |
| 正答の計算 | ブラウザ（分数・平方根・文字式・一次/二次/連立方程式） |
| 誤概念の推定 | **ブラウザで動くチームのモデル**（追加学習した misconception_model をWeb向けに変換。問題文・正答・生徒の解答から原因候補を順位付け） |
| 途中式の検証 | ブラウザの計算エンジン。モデル推論とは別に、対応する式の変形を確認 |
| 日本語の説明・声かけ | Gemini API |

## フォルダ構成

```
keisan-note-web/
├─ public/index.html        画面（ブラウザで動く計算エンジンとチームのモデルを含む）
├─ public/bert.js           チームのモデルをブラウザで動かすプログラム（外部ライブラリなし）
├─ public/data/models/team/ チームのモデルの重み（npm run pack-model で作る。同梱済み）
├─ public/data/             誤概念のベクトル（npm run build-data で作る。同梱済み）
├─ model/                   モデルを更新するときの入力先（通常起動には不要。必要に応じて作成）
├─ functions/_middleware.js 合言葉のチェック
├─ functions/api/           中継プログラム（ocr: 読み取り、report: 日本語の説明、translate: 文章題の英訳、health・check: 状態確認）
├─ lib/                     Gemini の呼び出しと指示文
├─ scripts/pack-model.mjs   メンバーのモデルを Web 用（fp16・25MB 以下に分割）にまとめる
├─ scripts/build-data.mjs   誤概念をベクトルにするスクリプト
├─ scripts/subjects.mjs     候補に残す単元の対応表（日本の単元 → Eedi の単元）
└─ data/                    再生成・評価用のCSV置き場（GitHub版には未収録。通常起動には不要）
```

通常起動に必要なのは、作成済みの `public/data/misconceptions.json`、`public/data/mis_emb.bin`、`public/data/models/team/` 一式です。モデルの更新や評価を行う場合のみ、元モデルやCSVを別途準備します。

## 必要なもの

- Node.js 22 以上（https://nodejs.org）。使用するWranglerの実行要件に合わせてください
- Gemini の API キー（Google AI Studio: https://aistudio.google.com/apikey）
- Cloudflareのアカウント（Cloudflare Pagesへ公開する場合に必要。ローカルでの起動だけなら不要）

## 1. 準備（最初の1回だけ）

リポジトリのルートから、Web版のフォルダへ移動します。

```sh
cd keisan-note-web/keisan-note-web
npm install
```

このフォルダをZIPから直接展開した場合は、そのフォルダで `npm install` を実行してください。

GitHubには、Web向けに変換したモデルと候補ベクトルが作成済みで含まれています。ファイルが揃っていれば、`pack-model` や `build-data` を実行せず「2. 手元で試す」に進めます。

### メンバーがモデルを作り直したとき

1. 新しい `misconception_model` フォルダ（config.json・model.safetensors・tokenizer.json などが入ったもの）を `model/misconception_model` に置く
2. 利用条件に従って取得した `misconception_mapping.csv` と `train.csv` を `data/` に置く。GitHub版にはこれらのCSVは含まれていません
3. 次の2つを実行する

```
npm run pack-model
npm run build-data
```

- `npm run pack-model` … モデルをWebで配れる形（`public/data/models/team/`、重み合計約45MB）にまとめます
- `npm run build-data` … 誤概念の候補を**日本の中学の計算分野と小学校の計算に絞り込んでから**、チームのモデルでベクトルにして `public/data/` に書き出します。処理時間は端末と候補数によって変わります
- 2つは必ずセットで実行してください（モデルだけ変えると、画面に「データ作成時とモデルが一致していません」と出ます）
- Web版の起動と上記の変換・ベクトル作成にはPythonやtransformers.jsは不要です。モデルの計算は `public/bert.js` が行います。重みは半精度に変換しているため、元のPython版と数値が完全一致することを保証するものではありません

GitHubのルートにある元モデルを変換する場合は、Web版の作業フォルダから `npm run pack-model -- ../../predict/misconception_model` と指定できます。

`.gitignore` はCSVと候補データを除外します。作成済みデータを更新してGitHubへ追加する場合は、対象ファイルがコミットに含まれているか確認してください。APIキーや合言葉を含む `.dev.vars` は追加しません。

### 候補の絞り込み

Eedi のデータはイギリスの教育課程なので、関数・図形・統計や、日本では高校で習う内容（数列、不等式、三角比など）の誤概念も入っています。
そこで `train.csv` を使い、次の単元の問題に出てくる誤概念 764 件だけを候補に残します（2,587 件から絞り込み）。

| 日本の単元 | 誤概念の数 |
|---|---|
| 正の数・負の数（中1） | 85 |
| 文字式・式の計算（中1・中2） | 111 |
| 一次方程式（中1） | 35 |
| 連立方程式（中2） | 29 |
| 式の展開と因数分解（中3） | 34 |
| 平方根（中3） | 29 |
| 二次方程式（中3） | 38 |
| 比・割合・速さ（小6〜中1、文章題用） | 103 |
| 小学校の計算（分数・小数・四則） | 300 |

それぞれの誤概念には日本の単元名が付き、レポートの「つまずきの単元」に使われます。
単元を増やしたり減らしたりしたいときは `scripts/subjects.mjs` を直して、もう一度 `npm run build-data` を実行してください。
絞り込まずに 2,587 件すべてを使うときは `npm run build-data -- --all` です。

### 精度を測る（任意）

```
npm run evaluate
```

この評価には `data/train.csv` と `data/misconception_mapping.csv` が必要です。通常のWeb版の起動には不要ですが、評価を実行する場合は別途準備してください。

確認した最新版ZIPのデータと現在の単元定義では、評価対象は計算分野873問・誤概念ラベルの付いた誤答2,005件です。データ・単元定義・実行オプションを変えると件数も変わります。結果は `eval/report.md` と `eval/results.json` に保存されます。以下は評価方法の説明であり、測定済みの精度や性能保証を示すものではありません。

| 比べる方式 | 内容 |
|---|---|
| A. 絞り込みなし | 誤概念 2,587 件すべてを候補にする |
| B. 計算分野に絞り込み | いまの `npm run build-data` の方式 |
| C. 計算分野を優先（+0.02 / +0.05 / +0.1） | 全件を残し、計算分野の誤概念のスコアにだけ加点する |

- 指標: Top-1（1位が正解）、Top-5（5位以内に正解）、MAP@25（Kaggle のコンペと同じ指標）
- 候補の絞り込み方式を比較するため、問題を5グループに分け、評価対象のグループ以外の問題から候補一覧を作ります。これは推論モデル自体を学習し直す交差検証ではありません
- 注意: Bは、候補作成に使う問題に出てこない誤概念を取りこぼす場合があります。候補に正解ラベルが残る割合と、検索順位の両方を確認してください。Cは全件を候補に残したまま加点する方式です
- 注意: 生徒の答えとして、4択の誤答の選択肢を使っています。実際の答案（手書きの自由記述）での精度とは異なることがあります
- **注意（重要）: 現在のモデルはtrain.csvのデータで学習しているため、同じデータによる評価は未知の問題に対する精度として扱えません。** 未知の問題への精度を測る場合は、一部の問題（例: `QuestionId % 5 == 0`）を学習から外して学習し直し、`npm run evaluate -- --holdout-fold 0` で外した問題だけを評価してください。元のモデルにこのオプションを付けるだけでは、学習データとの重複は解消されません
- オプション: `--limit 300`（問題数を減らして早く試す）、`--format latex`（問い合わせ文を学習時と同じ LaTeX のまま使う。既定は画面と同じ `plain`）

## 2. 手元で試す

1. `.dev.vars.example` をコピーして `.dev.vars` を作り、`GEMINI_API_KEY` と `APP_PASSCODE`（合言葉）を書く
2. `npm run dev`
3. ターミナルに表示されたURL（通常は http://localhost:8788 ）を開き、画面の下で合言葉を入れる

現在のデモと同じ `http://127.0.0.1:8012/` を使う場合は、`npm run dev -- --ip 127.0.0.1 --port 8012` で起動できます。すでに同じポートで起動している場合は、既存のプロセスを確認してから実行してください。

`.dev.vars` はローカル起動用です。Cloudflare Pagesの本番環境には、後述のシークレット設定を別途登録してください。

画面の下に「本番モード：Gemini とチームのモデルで動いています」と出て、「誤概念 764 件を読み込み済み（計算分野に絞り込み）（一致度 1.000）」と表示されれば成功です。
この「一致度」は、同じ誤概念名を計算し直したベクトルと作成済みベクトルの整合性チェックです。**診断の正解率や、原因候補の確からしさを表す数値ではありません。**

一致度が0.99より低い、またはモデルとデータの版の不一致が表示される場合は、重み・候補ベクトルが同じ版か確認してください。再作成が必要な場合は、上記の元モデル・CSVを準備してから、`npm run pack-model` と `npm run build-data` を実行します。

モデルの計算はブラウザで行います。初回ダウンロード、モデルの推論、Geminiの画像読み取り・レポート作成は別の処理です。待ち時間は問題の長さ・端末・通信状況によって変わるため、実際に利用する環境で確認してください。

## 3. 公開する

```
npx wrangler login
npx wrangler pages project create keisan-note --production-branch main
```

初回はプロジェクトを作成し、公開前にキーと合言葉を登録します。すでに同じプロジェクトがある場合は作成を省略します。プロジェクト名を変更する場合は、`package.json` のdeployコマンドと、以下の `--project-name` を合わせて変更してください。

```
npx wrangler pages secret put GEMINI_API_KEY --project-name keisan-note
npx wrangler pages secret put APP_PASSCODE --project-name keisan-note
npm run deploy
```

（Cloudflare のダッシュボードの「Workers & Pages」→ keisan-note →「設定」→「変数とシークレット」からも登録できます。登録後はもう一度 `npm run deploy` してください）

モデルを変更する場合は `GEMINI_MODEL` も設定します。指定するモデルは、利用するGemini APIで画像入力・必要な出力形式に対応しているか確認してください。公開手順の詳細は[Cloudflare公式CLIガイド](https://developers.cloudflare.com/workers/wrangler/commands/pages/)を参照してください。

デプロイ完了時に表示されるURLをPC・スマートフォンで開き、合言葉、画像読み取り、モデル読み込み、レポート作成を確認してください。`https://keisan-note.pages.dev` はURLの例です。
チームのモデルの重みは約45MBあるため、最初はWi-Fi環境での利用を推奨します。ブラウザのキャッシュが利用できれば再ダウンロードを抑えられますが、キャッシュの削除や端末の設定によって再取得が必要になります。

ローカルサーバーをトンネルで共有する一時URLと、Cloudflare Pagesの公開URLは別のものです。一時URLは共有接続の終了やURLの切り替えで利用できなくなるため、審査・継続利用にはアクセス可能な公開方法を確認してください。

## 合言葉とデータの保護

`APP_PASSCODE` を設定すると、合言葉を知っている人だけが次を使えます。

- Gemini の呼び出し（チームの利用枠を他人に使われないように）
- Eedi のデータ（`/data/`。Kaggle のデータを不特定多数に配らないように）

合言葉は公開READMEやソースコードに書かず、利用する講師へ別途共有してください。この仕組みは共通の合言葉によるアクセス制限で、講師別ログインや塾ごとのデータ分離を提供するものではありません。実用化時は、用途に合う認証・権限管理を検討してください。

## 個人情報の扱い（必ず読む）

画像の読み取りでは答案画像を、翻訳・レポート作成では問題文や生徒の解答などをGemini APIへ送信します。独自モデルがブラウザで動いていても、すべての処理が端末内で完結するわけではありません。

Googleの規約では、無料サービス（Unpaid Services）区分の入出力が製品改善に使われ、人による確認の対象になる場合があります。この区分には個人情報・機密情報を送信しないよう求められています。請求先が有効なプロジェクトを使う場合など、契約区分によって扱いが異なるため、「無料枠かどうか」だけで判断せず、実際のプロジェクト設定と[Gemini公式規約](https://ai.google.dev/gemini-api/terms?hl=ja)を確認してください。

- ハッカソンのデモは、サンプル答案か、自分たちで書いた答案を使う
- 実際の生徒の答案を扱う前に、契約区分、外部送信のルール、保存・削除の扱い、利用する塾で必要な説明・手続きを確認する
- 送信前に、氏名・学校名・生徒番号など、分析に不要な情報を取り除く

本アプリは講師が操作する用途を想定しています。生徒が直接利用するサービスへ広げる場合は、Gemini APIの対象年齢に関する利用条件も確認してください。有料区分への変更だけで、個人情報の取り扱いに関する確認がすべて不要になるわけではありません。

## 計算エンジンが扱える問題

| 種類 | 例 | 解答欄 |
|---|---|---|
| 数の計算（分数・正負の数・累乗） | `(-3)×(-4) - 2²` | 1つ |
| 平方根 | `√12 + √3`、`6/√3` | 1つ |
| 文字式の計算・展開 | `3(a+2b) - 2(a-b)`、`6x²y ÷ 3x` | 1つ |
| 一次方程式 | `3x + 4 = 13` | x = の欄 |
| 二次方程式 | `x² - 5x + 6 = 0` | x = の欄（2つの解は `,` で区切る） |
| 連立方程式 | `2x + y = 7, x - y = 2` | x と y の欄が分かれる |

連立方程式の問題は、式を `,` で区切って入力します。読み取りでも自動でこの形になります。
`x = 3, y = 1`、`(x, y) = (3, 1)` のどちらの書き方でも正しく判定します。

対応していないもの: 分数式（文字で割って分数が残る式）、3次以上の方程式、√ の中に文字がある式、因数分解の「形」の判定（展開して同じなら正解と判定します）。
これらは「判定できなかった問題」として理由を表示します。

## 文章を含む問題（文章題など）

読み取りでは、問題ごとに次の情報も取ります。読み取り確認の画面で直せます。

| 項目 | 内容 |
|---|---|
| 問題文 | 印刷された問題文（文章を含む）。小問は「(3)①」のように答案の番号で表示 |
| 式 | 式だけで解ける問題のときだけ入る。文章題では空 |
| 先生の丸つけ | ○（正解）・×（不正解）・なし |
| 単元 | 一覧から自動で選ぶ。「モデルの対象外」の単元は誤概念を推定しない |
| 正答 | 式で計算できない問題のときに、講師が入力する（任意） |

正誤の判定は「計算エンジン（式がある問題）→ 入力した正答 → 先生の丸つけ」の順に使います。どれもない問題は「判定できなかった問題」に出ます。
丸つけと計算エンジンの判定が食い違う問題は、読み取りの誤りかもしれないので注意を出します。

対応する文章題では、生徒が立てた式や、問題文から解釈できる条件を手がかりに、「式の立て方」と「その後の計算」のどちらを確認すべきか説明する場合があります。文章題全般の立式の正しさを保証するものではありません。
例えば、問題の条件に合う式が `120x + 200 = 920` である場合、そこから `120x = 920 + 200` と変形していれば、定数項を移す際の操作を確認する手がかりになります。
チームのモデルには、問題文の英訳（読み取りのときに Gemini が作る。手直しした問題文は /api/translate で訳し直す）を渡します。モデルは英語で学習しているためです。

### 対応できる範囲

| 内容 | 誤概念の推定 |
|---|---|
| 中学の計算・方程式（式だけの問題、文章題とも） | できる |
| 比・割合・速さの文章題 | できる（Eedi の該当単元 103 件を追加） |
| 関数・図形・データの活用 | 読み取り、入力された正答・丸つけなどを利用した正誤確認が可能な場合があります。誤概念の推定は対象外です |
| 高校の内容（複素数、二項定理、整式の割り算、解と係数の関係、高次方程式など） | 現在のモデルの対象単元外です。入力された正答や丸つけを利用できる場合がありますが、計算・診断できることを保証しません |

対象を広げる場合は、該当分野の誤答と誤概念ラベル、検証用の答案を準備し、候補の定義・推論・正誤確認の対応範囲を合わせて見直してください。

## サーバー版（keisan-note-app）との違い

- 正答の計算は sympy ではなく、ブラウザの計算エンジンで行います（連立方程式にも対応）
- チームのモデルは同じもの（メンバーの misconception_model）ですが、候補を計算分野の誤概念に絞り込んでいます。`train.csv` は絞り込みに使い、併用する方式（USE_TRAIN_KNN）は使っていません
- 講師向けレポートはGeminiで日本語化します。取得できなかった候補は英語表示になる場合があります。画面に再作成ボタンが表示された場合は再実行できます
