# ケアレスノート（Web版）

答案の写真から計算ミスの原因を推定し、講師向けのレポートを日本語で作るWebアプリです。
Cloudflare Pages に置くと、URL を開くだけで iPhone からも使えます。

| 処理 | どこで動くか |
|---|---|
| 答案の読み取り | Gemini API（中継プログラムがキーを持つ） |
| 正答の計算 | ブラウザ（分数・平方根・文字式・一次/二次/連立方程式） |
| 誤概念の推定 | **ブラウザで動くチームのモデル**（メンバーが学習させた misconception_model。app.py と同じ仕組み） |
| 日本語の説明・声かけ | Gemini API |

## フォルダ構成

```
keisan-note-web/
├─ public/index.html        画面（ブラウザで動く計算エンジンとチームのモデルを含む）
├─ public/bert.js           チームのモデルをブラウザで動かすプログラム（外部ライブラリなし）
├─ public/data/models/team/ チームのモデルの重み（npm run pack-model で作る。同梱済み）
├─ public/data/             誤概念のベクトル（npm run build-data で作る。同梱済み）
├─ model/                   メンバーの misconception_model を置く場所（zip には含めていない）
├─ functions/_middleware.js 合言葉のチェック
├─ functions/api/           中継プログラム（ocr: 読み取り、report: 日本語の説明、translate: 文章題の英訳、health・check: 状態確認）
├─ lib/                     Gemini の呼び出しと指示文
├─ scripts/pack-model.mjs   メンバーのモデルを Web 用（fp16・25MB 以下に分割）にまとめる
├─ scripts/build-data.mjs   誤概念をベクトルにするスクリプト
├─ scripts/subjects.mjs     候補に残す単元の対応表（日本の単元 → Eedi の単元）
└─ data/                    Eedi のデータ（misconception_mapping.csv と train.csv を同梱）
```

## 必要なもの

- Node.js 20 以上（https://nodejs.org）
- Gemini の API キー（Google AI Studio: https://aistudio.google.com/apikey）
- Cloudflare のアカウント（無料）

## 1. 準備（最初の1回だけ）

```
npm install
```

zip にはメンバーの最新モデル（misconception_model）を変換したものと、誤概念のベクトルが**作成済みで入っている**ので、これだけで次の「2. 手元で試す」に進めます。

### メンバーがモデルを作り直したとき

1. 新しい `misconception_model` フォルダ（config.json・model.safetensors・tokenizer.json などが入ったもの）を `model/misconception_model` に置く
2. 次の2つを実行する

```
npm run pack-model
npm run build-data
```

- `npm run pack-model` … モデルを Web で配れる形（`public/data/models/team/`、約45MB）にまとめます。数秒で終わります
- `npm run build-data` … 誤概念の候補を**日本の中学の計算分野と小学校の計算に絞り込んでから**、チームのモデルでベクトルにして `public/data/` に書き出します。数分かかります
- 2つは必ずセットで実行してください（モデルだけ変えると、画面に「データ作成時とモデルが一致していません」と出ます）
- Python や transformers.js は不要です。モデルの計算は `public/bert.js` が行い、メンバーの Python 版と同じ結果になることを確かめています（モデルカードの例文の類似度 0.6112 / 0.1481 / 0.2766 が一致）

### 候補の絞り込み

Eedi のデータはイギリスの教育課程なので、関数・図形・統計や、日本では高校で習う内容（数列、不等式、三角比など）の誤概念も入っています。
そこで `train.csv` を使い、次の単元の問題に出てくる誤概念 764 件だけを候補に残します（2,587 件から絞り込み）。

| 日本の単元 | 誤概念の数 |
|---|---|
| 正の数・負の数（中1） | 85 |
| 文字式・式の計算（中1・中2） | 111 |
| 一次方程式（中1） | 35 |
| 連立方程式（中2） | 29 |
| 式の展開と因数分解（中3） | 34 |
| 平方根（中3） | 29 |
| 二次方程式（中3） | 38 |
| 比・割合・速さ（小6〜中1、文章題用） | 103 |
| 小学校の計算（分数・小数・四則） | 300 |

それぞれの誤概念には日本の単元名が付き、レポートの「つまずきの単元」に使われます。
単元を増やしたり減らしたりしたいときは `scripts/subjects.mjs` を直して、もう一度 `npm run build-data` を実行してください。
絞り込まずに 2,587 件すべてを使うときは `npm run build-data -- --all` です。

### 精度を測る（任意）

```
npm run evaluate
```

train.csv の計算分野の問題（768問、誤概念のラベルが付いた誤答 1,771 件）で、チームのモデルの精度を測ります。数十秒〜数分で終わり、結果は `eval/report.md`（表）と `eval/results.json` に保存されます。

| 比べる方式 | 内容 |
|---|---|
| A. 絞り込みなし | 誤概念 2,587 件すべてを候補にする |
| B. 計算分野に絞り込み | いまの `npm run build-data` の方式 |
| C. 計算分野を優先（+0.02 / +0.05 / +0.1） | 全件を残し、計算分野の誤概念のスコアにだけ加点する |

- 指標: Top-1（1位が正解）、Top-5（5位以内に正解）、MAP@25（Kaggle のコンペと同じ指標）
- 公平に比べるため、問題を5つに分けた交差検証で測ります（絞り込みの候補は、評価する問題を除いた問題から作る）
- 注意: B は、計算分野の問題に1回も出てこない誤概念を取りこぼします。データだけで計算すると、新しい問題では正解の誤概念の約27%が候補から外れます（計算分野の誤概念の53%は、1問にしか出てこないため）。C はこれを避ける方式です
- 注意: 生徒の答えとして、4択の誤答の選択肢を使っています。実際の答案（手書きの自由記述）での精度とは異なることがあります
- **注意（重要）: メンバーのモデルは train.csv の全データで学習しているため、train.csv で測ると答えを見たテストになり、実際より高く出ます。** 公平に測るには、メンバーに一部の問題（例: `QuestionId % 5 == 0`）を学習から外してもらい、`npm run evaluate -- --holdout-fold 0` でその問題だけを評価してください
- オプション: `--limit 300`（問題数を減らして早く試す）、`--format latex`（問い合わせ文を学習時と同じ LaTeX のまま使う。既定は画面と同じ `plain`）

## 2. 手元で試す

1. `.dev.vars.example` をコピーして `.dev.vars` を作り、`GEMINI_API_KEY` と `APP_PASSCODE`（合言葉）を書く
2. `npm run dev`
3. ブラウザで http://localhost:8788 を開き、画面の下で合言葉を入れる

画面の下に「本番モード：Gemini とチームのモデルで動いています」と出て、「誤概念 764 件を読み込み済み（計算分野に絞り込み）（一致度 1.000）」と表示されれば成功です。
一致度が 0.99 より低いときは、`npm run build-data` をやり直してください。

チームのモデルの計算はブラウザで行うので、1問あたり 0.1〜0.5 秒ほどかかります（パソコン・最近の iPhone の目安）。

## 3. 公開する

```
npx wrangler login
npm run deploy
```

初回はプロジェクト（keisan-note）を作るか聞かれるので、作成を選びます。続けて、キーと合言葉を登録します。

```
npx wrangler pages secret put GEMINI_API_KEY --project-name keisan-note
npx wrangler pages secret put APP_PASSCODE --project-name keisan-note
npm run deploy
```

（Cloudflare のダッシュボードの「Workers & Pages」→ keisan-note →「設定」→「変数とシークレット」からも登録できます。登録後はもう一度 `npm run deploy` してください）

公開された URL（`https://keisan-note.pages.dev` など）を iPhone の Safari で開けば使えます。
チームのモデルは初回だけ約45MBをダウンロードするので、最初は Wi-Fi で開いてください。2回目からはブラウザに保存されます。

## 合言葉とデータの保護

`APP_PASSCODE` を設定すると、合言葉を知っている人だけが次を使えます。

- Gemini の呼び出し（チームの利用枠を他人に使われないように）
- Eedi のデータ（`/data/`。Kaggle のデータを不特定多数に配らないように）

合言葉は講師に口頭などで伝えてください。より厳しく制限したいときは、Cloudflare Zero Trust（50人まで無料）でメールアドレスによるログインをかけられます。

## 個人情報の扱い（必ず読む）

Gemini の**無料枠**に送った画像は、Google がサービス改善に使い、人が確認することがあります。

- ハッカソンのデモは、サンプル答案か、自分たちで書いた答案を使う
- 実際の生徒の答案を扱うなら、Gemini の有料枠に切り替える
- どちらの場合も、氏名欄は隠してから撮影する

## 計算エンジンが扱える問題

| 種類 | 例 | 解答欄 |
|---|---|---|
| 数の計算（分数・正負の数・累乗） | `(-3)×(-4) - 2²` | 1つ |
| 平方根 | `√12 + √3`、`6/√3` | 1つ |
| 文字式の計算・展開 | `3(a+2b) - 2(a-b)`、`6x²y ÷ 3x` | 1つ |
| 一次方程式 | `3x + 4 = 13` | x = の欄 |
| 二次方程式 | `x² - 5x + 6 = 0` | x = の欄（2つの解は `,` で区切る） |
| 連立方程式 | `2x + y = 7, x - y = 2` | x と y の欄が分かれる |

連立方程式の問題は、式を `,` で区切って入力します。読み取りでも自動でこの形になります。
`x = 3, y = 1`、`(x, y) = (3, 1)` のどちらの書き方でも正しく判定します。

対応していないもの: 分数式（文字で割って分数が残る式）、3次以上の方程式、√ の中に文字がある式、因数分解の「形」の判定（展開して同じなら正解と判定します）。
これらは「判定できなかった問題」として理由を表示します。

## 文章を含む問題（文章題など）

読み取りでは、問題ごとに次の情報も取ります。読み取り確認の画面で直せます。

| 項目 | 内容 |
|---|---|
| 問題文 | 印刷された問題文（文章を含む）。小問は「(3)①」のように答案の番号で表示 |
| 式 | 式だけで解ける問題のときだけ入る。文章題では空 |
| 先生の丸つけ | ○（正解）・×（不正解）・なし |
| 単元 | 一覧から自動で選ぶ。「モデルの対象外」の単元は誤概念を推定しない |
| 正答 | 式で計算できない問題のときに、講師が入力する（任意） |

正誤の判定は「計算エンジン（式がある問題）→ 入力した正答 → 先生の丸つけ」の順に使います。どれもない問題は「判定できなかった問題」に出ます。
丸つけと計算エンジンの判定が食い違う問題は、読み取りの誤りかもしれないので注意を出します。

文章題で生徒が式を立てていれば、その式を手がかりに「式の立て方（立式）のミス」と「その後の計算のミス」を分けて示します
（例: 120x + 200 = 920 は正しく、120x = 920 + 200 で移項の符号を間違えている）。
チームのモデルには、問題文の英訳（読み取りのときに Gemini が作る。手直しした問題文は /api/translate で訳し直す）を渡します。モデルは英語で学習しているためです。

### 対応できる範囲

| 内容 | 誤概念の推定 |
|---|---|
| 中学の計算・方程式（式だけの問題、文章題とも） | できる |
| 比・割合・速さの文章題 | できる（Eedi の該当単元 103 件を追加） |
| 関数・図形・データの活用 | 読み取りと正誤の判定のみ（このアプリは計算分野に絞っているため） |
| 高校の内容（複素数、二項定理、整式の割り算、解と係数の関係、高次方程式など） | 読み取りと正誤の判定のみ。Eedi のデータに誤概念がほぼない（複素数・二項定理・整式の割り算は 0 件）ため |

高校の内容まで診断したい場合は、Eedi 以外のデータ（自分たちで集めた誤答と誤概念のラベル）が必要です。

## サーバー版（keisan-note-app）との違い

- 正答の計算は sympy ではなく、ブラウザの計算エンジンで行います（連立方程式にも対応）
- チームのモデルは同じもの（メンバーの misconception_model）ですが、候補を計算分野の誤概念に絞り込んでいます。`train.csv` は絞り込みに使い、併用する方式（USE_TRAIN_KNN）は使っていません
- 講師向けレポートは Gemini がすべて日本語で書きます。日本語化に失敗したときは「日本語の説明を作り直す」ボタンが出ます
